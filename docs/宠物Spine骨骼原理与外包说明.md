## 0. 一句话结论

- 宠物用 **2D Spine 骨骼动画**（已定，不推翻）。
- **一套骨骼** 可挂 **N 个动画** + **N 种皮肤**，三者解耦，这是省钱的核心。
- **全项目只有一套骨骼：四足，猫狗共用**（2026-09-07 定）。
  原「拟人主宠单独一套」的方案**已废弃**，理由见 `docs/2D-Spine迁移与接入.md`
  「为什么砍掉拟人主宠」。**外包只按一套骨架报价。**
- 换狗**不是随便换图就行**：图被「渔网(mesh/UV)」锁死，改形状必须回 Spine 改网格。
- 外包别照那个猫包的规模（139 动画/59 皮肤）报价，按玩法实际需求砍到 **约 18 个动画 + 5~10 花色**。

## 1. 59 猫素材包与本项目的关系

目录：`docs/59种spine卡通猫咪小猫白猫动物模拟养成骨骼动画源文件游戏/`
性质：**从某款商业猫咖手游扒来的 Spine 素材原始包**（不是文档，只是暂放于 `docs/`）。

| 素材包目录 | 内容 | 对应项目 |
| --- | --- | --- |
| `spine/` + `json/` | 猫骨骼 `Cat` + 59 种花色 PNG | `assets/resources/spine/pet_cat/`（四足小宠） |
| `附送UI/`（家具/特效 Spine，17 套 `.atlas.txt`） | 猫咖场景素材 | `assets/resources/spine/` 下各家具目录 |
| `附送UI/data/` | Unity 序列化数据表/本地化 | **用不了，忽略** |

> ⚠️ **合规红线**：这是扒来的商业游戏美术，现在项目里当**临时兜底占位**（`PetStage.ts` 的 `FALLBACK_SKELETON = 'pet_cat/Cat'`）跑玩法可以，但**上架前必须换成原创或正版授权**，否则有侵权风险。

### 1.1 素材包文件结构详解（`spine/` vs `json/` vs `附送UI/`）

猫本体有 `spine/` 和 `json/` 两个文件夹，它们是**同一只猫的「源 → 成品」两种导出**，不是配套、是二选一：

```
【源 · 只在 spine/ 里有】
spine/0cat.spine            Spine 编辑器母版工程（唯一可编辑；改骨骼/网格/动画/皮肤都在这）
spine/images/01…59/*.png    源分件图：59 个文件夹=59 花色，每个约 64 张部件图
                            （Head/Body/Ear_L/Eye_*/Mouth_*/*_Leg_*/Paw*/Tail…；
                             个别没改名的叫 Artboard NNN，也是部件图）
        │  在 0cat.spine 里绑骨+铺网格，导出打包
        ├──→【成品A·二进制】 spine/Cat.skel + spine/Cat.atlas(59页) + spine/Cat.png…Cat59.png
        └──→【成品B·文本】   json/Cat.json  + json/Cat.atlas(6页)  + json/Cat.png…Cat6.png
```

- **`spine/`**：完整套装 = 母版 + 源分件图 + 二进制成品（`.skel` + 59 页图集）。
- **`json/`**：只有成品 = 文本骨骼（`.json`）+ 6 页图集。**没有源文件、不能编辑**。
- **两个 `Cat.atlas` 效果相同**：区域名（`01/Head`…`68/Head` 共 59 套）完全一致，渲染结果一样；只是打包页数不同（59 页 vs 6 页）。
- **配对规则**：`atlas` 必须和它**自己那套 PNG** 一起用，不能跨文件夹混；骨骼数据（`.skel`/`.json`）配哪套图集都行。
- **项目实际用**：Cocos 读 `json/` 的 **`Cat.json`**（文本骨骼），配 59 页那套贴图，放在 `assets/resources/spine/pet_cat/`。
- **要改这只猫**：打开 `spine/0cat.spine`（正版 Spine 3.8）→ 改 → 导出 JSON → 替换进 `pet_cat/`。

`附送UI/` 与这只猫**无关**，是那款猫咖游戏附赠的一批**独立**家具/道具/特效 Spine（各自成套）+ 用不了的 Unity 数据表。

| 文件 | 所在 | 类别 | 作用 |
| --- | --- | --- | --- |
| `0cat.spine` | spine/ | 源·母版 | 唯一可编辑的工程 |
| `images/01…59/*.png` | spine/ | 源·分件图 | 59 花色的原始拆件素材 |
| `Cat.skel` | spine/ | 成品·骨骼(二进制) | 骨骼数据的一种导出 |
| `Cat.atlas`(59页) | spine/ | 成品·图集清单 | 部件→贴图坐标 |
| `Cat.png…Cat59.png` | spine/ | 成品·贴图 | 每张=一种花色 |
| `Cat.json` | json/ | 成品·骨骼(文本) | **Cocos 用这个** |
| `Cat.atlas`(6页) | json/ | 成品·图集清单 | 同一套区域名，打包不同 |
| `Cat.png…Cat6.png` | json/ | 成品·贴图 | 59 花色塞进 6 张 |

## 2. Spine 三件套：`.json` / `.atlas` / `.png`

一套 Spine 动画由三种文件配合，缺一不可：

| 文件 | 是什么 | 作用 |
| --- | --- | --- |
| `Cat.json` | 骨骼动画数据（文本） | 定义骨头、插槽、**网格(mesh)**、动画、皮肤——「怎么动」的全部逻辑 |
| `Cat.atlas` | 图集清单（文本） | 坐标索引表：告诉引擎每个部件在**哪张 PNG 的哪个矩形** |
| `Cat*.png` | 贴图（图片） | 真正的像素 |

运行流程：json 说「画 Head」→ atlas 查 Head 在哪张图哪块 → 从对应 PNG 取像素贴上。
本包骨骼版本 **Spine 3.8.75**（引擎 spine 模块版本必须对齐，否则不出画面）。

加载：`resources.load('spine/pet_cat/Cat', sp.SkeletonData)`，Cocos 按同名自动配对 json/atlas/png。

## 3. 皮肤(skin)机制：一套骨骼 × N 花色

- `Cat.atlas` 是**多页图集**：59 页，一页对应一张 PNG（`Cat.png`…`Cat59.png`）。
- `Cat.json` 里对应定义了 **59 个皮肤**：`"001"`…`"059"`。
- 切换 `skel.setSkin('001'..'059')` 即换花色，骨骼、动画不变。
- 本包**没有 `default` 皮肤**，挂载后必须显式 `setSkin('001')`，否则整只不可见。
- 非预乘直通道 PNG 要 `skel.premultipliedAlpha = false`，否则出白框。

「皮肤系统」= 用 Spine 的 skin 机制，一副骨架挂多套外观（花色/换装），运行时 `setSkin` 切换。
换装（帽子/衣服）也是 skin，可 mix-and-match 组合。**注意**：换装/网格需 Spine **Pro**。

## 4. 骨骼 / 动画 / 皮肤 三者关系（1 : N : N）

```
一套骨骼（演员）
├── 139 个动画   ← 绑在骨骼上，该骨骼的所有皮肤/物种全部共用
└── 59 种皮肤     ← 绑在骨骼上，同骨骼皮肤可互换；不能跨骨骼
```

| | 同一套骨骼内（四足猫↔狗） | 跨骨骼（如四足↔直立人形） |
| --- | --- | --- |
| **动画** | ✅ 全部共用 | ❌ 各做各的 |
| **皮肤/换装** | ✅ 可互换/通用 | ❌ 不能共用 |

> 右列只是说明「跨骨骼有多贵」，**本项目不会出现这种情况**——全项目只有一套四足骨架。
> 这也正是砍掉拟人主宠的直接收益：动画和配饰都只做一份。

- 绑骨**做一次**，之后所有动画、皮肤都站在它上面。
- 动画**按条**叠加（最贵）；皮肤**按种**叠加（较便宜）；互不影响。

## 5. 「换成狗」能不能直接换图？——渔网(mesh/UV)的约束

**不能随便换。** 骨骼确实不变，但 `Cat.json` 里每个部件是 **mesh + 焊死的 UV**：它规定「图的哪个像素贴到网格哪个顶点」。

- 59 张图能通用，是因为它们都按**同一套渔网**画的（同轮廓、同位置、同朝向），不是因为它们是猫。
- 我（AI）能**读到**渔网的全部数据（uvs/vertices/hull），也能据此在**原轮廓内精准填色**。
- 但**渔网的形状是固定的**：图被贴进网里、按网的轮廓拉伸。想要垂耳/长鼻（狗的轮廓），就**改了形状 → 必须回 Spine 改网格**，从图片侧绕不过去。

换狗三条路线：

| 路线 | 做法 | 能动 | 像狗 | 谁做 |
| --- | --- | --- | --- | --- |
| A 换色 | 原轮廓内重上色 | ✅ | ❌「狗色的猫」 | AI 可独立完成 |
| B 复用骨骼 reskin | 出狗分件图 + Spine 重贴网格 | ✅ | ✅ 真像 | 分件图 AI，reskin 需 Spine |
| C 新骨架 | PSD→Spine（如 K-ulucay MCP）另起骨架 | ⚠️动作少 | 🔸中 | 需装 MCP + 素材 |

> 关于 MCP：GitHub 有 Spine MCP（1425sd/spine-MCP、sneurlax、K-ulucay），但 CLI 类**必须本机装正版 Spine**且**做不了 mesh 绑定**；官方也无编辑器脚本 API。改网格这步 MCP 救不了。

## 6. 帧序列 vs 骨骼：小游戏为什么选骨骼

对养成+换装+多花色+多动作的游戏，**骨骼是对的**，帧序列会崩：

- 微信小游戏包体极紧；帧序列逐帧存图，`动作×花色×朝向×帧数` **组合爆炸**，装不下。
- 换装靠帧序列要预渲每种组合（2^N），**做不到**。
- 骨骼：换皮肤/挂点极省包、加动作只加数据不重画、动画可混合插值。

帧序列该用在：**特效/粒子、一次性演出、极简固定角色**。行业标准是**混用**（宠物骨骼 + 特效帧序列）。

## 7. 骨架原型：划分标准与设计规范

**划分判据 = 骨骼拓扑（骨头数量/层级/父子关系）是否相同。**
- 只是比例/大小/毛色/耳形不同 → **同原型**（调骨 + 换图 + 缩放 + skin）。
- 骨头结构变了（四足→直立、增删骨） → **新原型**。

**每套原型骨架的设计规范（六条）：**
1. 骨骼**命名统一**（`Head`/`Tail_A`/`L_`/`R_`…），动画靠骨名驱动。
2. 骨头取**最大公约数**（共用角色需要的都留，宁多勿缺）。
3. **setup pose 标准化**（朝向、原点、缩放单位、站姿）。
4. **挂点 `socket_`** 规范齐全（换装点）。
5. 可换部件都做成 **skin placeholder**。
6. 四足腿用**两骨 IK**（参照 Spine 官方 Raptor：脊柱分段 + 每腿两骨 IK + 尾/耳）。

**本项目只有一套原型：**

- **四足（猫狗共用）** —— 现有猫骨架即是：
  `root → Body → Body_B → Body_C`（脊柱 3 段）+ `Head → Ear_L/Ear_R` + `Tail_A~D`（尾 4 段）+ 四腿分段。

> 原「原型 B · 人形（拟人主宠）」已废弃。真要新增原型的判据仍是上面那条
> **骨骼拓扑是否变了**——比如做一只腊肠犬只是比例变化（同原型），
> 而做一只直立行走的角色才是新原型。

## 8. 猫狗共用 + 行业实践

- **共用一套骨骼是全行业标准做法**，2D（Spine mix-and-match）和 3D（Unity/Unreal 骨骼重定向）都是。
- 原因：动画最贵，共用骨架 = 动画做一次多角色共享，否则内容一多成本爆炸。
- 大厂做法：先定**骨架原型表**（四足/人形/飞禽…），同原型共用，跨原型才新绑；英雄角色开小灶。
- 代价：共骨角色动作会「神似」，靠调骨/换图/个别专属动画区分；别把结构差太远的硬塞一套。

## 11. 外包成本拆解与精简需求

三大工序：

| 项目 | 是什么 | 本包量 | 行情（RMB） | 你的实际需求 |
| --- | --- | --- | --- | --- |
| ① 绑骨 + mesh | 搭骨架、铺网格、刷权重（地基，一次性） | 60+ 部件 | ¥5千–1.5万/套 | **1 套**（四足猫狗共用） |
| ② 动画 | 逐条 K 关键帧（**最贵，按条**） | 139 个 | ¥300–1500/个 | **约 18 个** |
| ③ 花色皮肤 | 换贴图不换骨/动画 | 59 种 | ¥300–800/种 | **5~10 种** |

- 别按 139 个动画报价（会白花十几万）。按「**1 套绑骨 + ~18 动画 + 5~10 花色**」谈。
- 加**狗 reskin**：¥3千–1万（同骨架换网格剪影与贴图，动画和配饰全部复用，不用重做）。
- **整包中小体量：¥2万–5万。**
- **不要报拟人主宠。** 该方案已废弃；它含换装原本要 ¥1.2万–3万+，是全项目最贵的单项。
- 赛跑动画极便宜：只需 `race_run` + `race_win` 两个（其余复用）。
- **`idle` 要清醒姿势**，别交睡姿版——它是玩家开局第一眼看到的动画（见接入说明）。

**给外包的硬要求：**
- 交付 `.spine` 工程源文件 + 分件图 + 导出数据（别只给成品）。
- 保留 skin 结构、命名规范（花色 `fur_*`、饰品 `acc_*`、挂点 `socket_`）。
- 导出版本对齐引擎 runtime（先确认版本号）。
- **必须正版 Spine**（合规红线），验收时 `.spine` 能在正版打开。

## 12. 代码 / AI 能调整什么、不能调整什么（动画侧）

| 类型 | 能否 |
| --- | --- |
| 调速度（走路提速当冲刺）、选播放、裁剪、循环、镜像、改名、简单幅度缩放、换部件时机 | ✅ 代码/JSON 直接改 |
| 微调个别骨头的现有关键帧（小修） | ⚠️ 能试，需预览确认，来回几轮 |
| 从零做新动作 / 大幅重摆姿势 / 让动作变自然 | ❌ 需 Spine 编辑器，人来做 |

原因：动画是几百上千关键帧协调的结果，无可视化反馈时手写数字调不自然；Spine 编辑器就是为此存在。

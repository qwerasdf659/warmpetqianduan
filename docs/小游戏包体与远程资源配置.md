> 微信小游戏**主包上限 4MB**。本工程 `resources` 现有约 60MB（59 花色猫 20MB、
> 墙纸地板 26MB、家具骨架 6MB、前景陈设 3MB），必须走远程资源才能上线。
> 本文只记实际要点的操作与坑，配完一次基本不用再动。

## 结论先说

- 主包只放**代码 + 首屏必需**，其余资源放 CDN，运行时下载并缓存。
- `assets/resources` 已经是一个 Bundle（见 `assets/resources.meta` 的 `isBundle: true`），
  所以**不需要改代码**：把它配成远程即可，`resources.load()` 的调用方式完全不变。
- 分包（subpackage）总量上限 20MB，我们 60MB 装不下，**只有远程资源这一条路**。

## 一、资源服务器：用 Sealos 对象存储

后端已经在 Sealos（北京区，`sealosbja`）上，直接用它自带的**对象存储**放资源，
不用另找 CDN、也不用让后端开静态目录。

在 Sealos 桌面打开 **对象存储（Object Storage）**：

1. 新建 Bucket，例如 `warmpet-assets`。
2. **权限必须设为 `publicRead`（公开读）**。默认是私有，私有桶的对象要带签名才能访问，
   小游戏这边是裸 URL 下载，私有会全部 403。
3. 建好后面板会给出访问域名，形如：

```
https://objectstorageapi.bja.sealos.run/<你的-bucket-名>
```

这个地址就是后面要填的**资源服务器地址**。以实际面板显示为准，别照抄本文。

### 微信后台必须配白名单

小游戏管理后台 →「开发管理 → 开发设置 → 服务器域名」，
把对象存储域名（如 `objectstorageapi.bja.sealos.run`）加到 **downloadFile 合法域名**。

不配的话真机一律下载失败。开发者工具勾了「不校验合法域名」时看不出问题，
这是最常见的「本地好、真机白屏」原因。

> 注意这和 `request` 合法域名是两个不同的列表：
> 后端 API 域名配在 request，资源下载域名配在 downloadFile，两个都要有。

## 二、编辑器里配置远程 Bundle

**不要手改 `profiles/v2/packages/builder.json`。** 那是编辑器的配置缓存，
手改会被覆写，改错还会让构建异常。一律在构建面板操作。

1. Cocos Creator →「项目 → 构建发布」，平台选**微信小游戏**。
2. 展开 **Bundle 配置 / Asset Bundle** 一栏，找到 `resources` 这个 Bundle：
   - 勾选 **配置为远程包**（Is Remote Bundle）
   - 压缩类型建议 **Merge Dep**（合并依赖，减少请求数）
3. 面板上方 **资源服务器地址**（Resource Server Address）填第一步拿到的桶地址，
   形如 `https://objectstorageapi.bja.sealos.run/warmpet-assets`。
4. 建议同时勾 **MD5 Cache**：文件名带 hash，换版本不会读到旧缓存。
5. 点「构建」。

构建完成后 `build/wechatgame/` 结构会变成：

- 主包里只剩代码 + 少量必需资源（目标 < 4MB）
- 多出一个 `remote/` 目录，里面是 `resources` Bundle 的全部内容

## 三、把 remote 目录传上去

把 `build/wechatgame/remote/` 下的**全部内容**上传到桶根目录。
注意是「remote 里面的东西」，不是 remote 这个文件夹本身——
传错一层会多出一级路径，全部 404。

传完后浏览器直接打开这个地址，**必须返回 JSON**：

```
https://objectstorageapi.bja.sealos.run/<bucket>/resources/config.json
```

只要它 404，游戏就会卡在加载、控制台报 `Bundle resources 加载失败`。
先验这一条，再去开发者工具，能省很多来回。

上传方式二选一：

- Sealos 对象存储面板直接拖拽上传（文件多，建议按目录分批）。
- 用 s3 客户端（如 `mc`、`s3cmd`、rclone）批量同步，桶的 AK/SK 在面板里能拿到。
  文件数量上千时这个更靠谱。

**以后每次重新构建，`remote/` 都要重新上传。** 忘了传的症状是「改动没生效」，
很容易误判成代码问题。

## 四、验证顺序（别跳步）

1. 浏览器打开 `https://objectstorageapi.bja.sealos.run/<bucket>/resources/config.json`
   → 必须返回 JSON。返回 403 = 桶不是 publicRead；404 = 上传路径错了一层。
2. 微信开发者工具打开 `build/wechatgame`，**先勾**「不校验合法域名」跑通，
   确认资源能下载、游戏能进。
3. 再**取消勾选**，确认 downloadFile 白名单配对了——只有这步过了才等于真机能跑。
4. 真机预览（扫码），看首包大小是否 < 4MB。

## 五、顺带该做的减重（和远程不冲突）

即使配了远程，这几项也值得做：

- **删 `assets/resources/models`**：3D 管线已退役（见 `spine-2d-pet` 规则），纯遗留。
- **压缩贴图**：`deco_tiles` 的 55 张墙纸/地板单张 300KB~1MB，是纯色/简单纹理，
  在 `.meta` 里改压缩格式或降分辨率，这块能砍到 1/5 以下。
- **`Cat.json` 8MB**：59 花色猫的骨骼是 JSON 文本。导出成 `.skel` 二进制体积会小很多
  （素材方给的 `spine/Cat.skel` 是 4.2MB，约省一半），但要确认运行时读得了。

## 六、踩过 / 会踩的坑

- **主包上限是 4MB，不是整包 4MB**。远程资源不计入主包，但分包计入 20MB 总量。
- **开发者工具「不校验合法域名」会掩盖白名单问题**。本地能跑不代表真机能跑，
  必须取消勾选再验一次。
- **`remote/` 忘了重新上传**：改了资源、重新构建，但没传新的 `remote/`，
  真机读到的还是旧资源，症状是「改动没生效」，很容易误判成代码问题。
- **桶权限忘了改 publicRead**：症状是 403 而不是 404，容易误判成路径问题。
- **上传时多套了一层目录**：传的是 `remote/` 文件夹本身而不是它的内容，
  正确路径应该是 `<bucket>/resources/config.json`，错了会变成
  `<bucket>/remote/resources/config.json` → 全部 404。
- **request 和 downloadFile 白名单是两个列表**：后端 API 配在前者、
  资源下载配在后者。只配了 request 的话 API 正常但资源全下不来。
- 构建请在**编辑器构建面板**里做，不要用 CLI —— 编辑器开着时跑 CLI 构建会
  抢同一份 `temp/`、`library/`，产物互相覆盖，症状是预览白屏 +
  `Unable to resolve bare specifier '__unresolved_N'`（见 `cocos-toolchain` 规则）。

# AI 出图 → 可入包游戏素材

产出：背景透明、已裁边、尺寸受控的 PNG，放进 `assets/resources/` 就能被
`resources.load()` 加载。全部脚本在 `scripts/`，依赖 `pngjs` 与 `playwright`。

## 工作流

```
- [ ] 1. 生成：一个元素一张图，纯白底、留大量空白
- [ ] 2. 抠底：边缘泛洪填充（保住内部白色）+ 自动裁边
- [ ] 3. 校验：叠深色/浅色两种底看残留与破洞
- [ ] 4. 缩放入包：长边降到 512，落到 resources/<模块>/
- [ ] 5. 验收：无头浏览器读运行时真值，不靠肉眼截图
```

## 1. 生成：一次一个元素

**一次只生成一个元素。** 一张图里塞四栋小屋时模型会自作主张改主题
（要「洗浴间/花园/育婴室/护理室」，给的是「春夏秋冬四季小屋」）。

```bash
export LOVART_ACCESS_KEY=... LOVART_SECRET_KEY=...
python3 ~/.cursor/skills/lovart-api/scripts/agent_skill.py chat \
  --prompt "<见下面的提示词骨架>" --json --download --output-dir .build/lovart/raw
```

提示词必须写全这四组，缺一样就飘：

| 约束 | 内容 |
| --- | --- |
| 背景 | **纯白色背景、元素居中、四周留大量空白**、不要投影落在背景上、无渐变 |
| 形态 | 正面平视、独立小物件，**明确写「不要画成一整个场景」** |
| 风格 | 日系手绘赛璐璐、扁平上色、左上方柔和光照、**细的同色系描边（见下）** |
| 配色 | 写十六进制（本项目：`#FFFCF7` `#FAEBCD` `#D9A05B`），别写「暖色调」 |

负面清单固定写上：文字、人物、宠物动物、3D 渲染感、真人照片风格。

### 「一次一个元素」对「两个并排」同样适用

让模型画「两个并排的相框」，它给的是**一整块实心木板**：四角不透明、
外圈 95% 实心、填充率 93% —— 正是要消灭的贴纸感。改成「只画一个相框，
不要画两个」立刻正常。同理别写「两个碗」「一对花盆」这类复数主体。

配套要在提示词里堵死背景板：

```
整张图里除了这一个 X 之外不要有任何东西：不要画墙、不要画背景板、
不要画托底的方块、不要有投影落在背景上。X 之外的区域必须是纯白的。
```

### ⚠️ 重新生成后必须按时间取最新的那张

`lovart/raw/<name>/` 里会累积新旧多张 PNG。导入脚本若写
`Get-ChildItem ... | Select-Object -First 1`（**没排序**）会挑到旧图，
症状是「重出了但画面没变化」，极易误判成提示词没生效。

必须 `Sort-Object LastWriteTime -Descending` 再取第一个。
这次靠 `seam-check.mjs` 的外圈主色仍是深棕才发现，肉眼对比根本看不出来。

### ⚠️ Lovart 断连：先分清「间歇」还是「整体不可用」

都报 `Connection failed after 1 attempts: Remote end closed connection`，
但处理方式不同 —— **先跑一个只读接口判断**：

```bash
python3 ~/.cursor/skills/lovart-api/scripts/agent_skill.py query-mode
```

- **只读接口正常、只有 `chat` 掉线** = 间歇性，等几十秒重试即可（多数情况）。
- **只读接口也断** = 服务整体不可用，重试无意义，改走别的路
  （如先用矢量绘制顶上，等服务恢复再出图）。

两种都不是配置或鉴权问题，别去翻 key。批量任务里个别失败会以 `exit=1` 结束、
但脚本会继续跑下一个，所以**跑完要检查每一项的 exit code**，
只看最后几行会漏掉中间失败的那几张（这次 14 张里有 2 张这样失败）。

### 尺寸要按「屏幕上的实际渲染尺寸」验收，不是按图的像素

`placeArt` 等比缩放 `scale = min(框宽/图宽, 框高/图高)`。竖图（如 478x512 的
壁龛）**永远被高度卡住** —— 把框加宽根本不会让图变大。
实测把分区框从 150 加宽到 194，图只从 75x80 变成 80x86（大 7%），
玩家看不出任何变化，白改一轮。

用 `ui-visual-parity` 的 `probe-artsize.mjs` 读**运行时渲染尺寸**验收。

### ⚠️ 千万不要写「深棕色描边」——这是「像贴上去的」的根源

一整批 16 张图都写了「圆润的深棕色描边 `#4A3728`」，结果**每个物件都被一圈
深棕完整封闭**，视觉上就是「一张贴纸剪下来贴上去」。返工了三轮才定位到 ——
前两轮都在改位置和尺寸，方向全错，因为这跟摆位毫无关系。

**要改的是描边的颜色和均匀度，不是取消描边** —— 具体写法见下一节
「但『只深一到两档』会矫正过头」，**以那一节为准**。

<details>
<summary>已被推翻的写法（2026-09-15 前，别再照抄）</summary>

当时的结论是「竞品物件几乎没有外轮廓线」，并这样写提示词：

```
**不要用深棕色或黑色的粗描边把物体整个包起来**：
轮廓线要非常细、并且用比该处填充色只深一到两档的同色系颜色
（例如粉色部件用略深的粉、木色部件用略深的木色），
让物体靠色块本身的深浅区分层次，看起来是融进画面的而不是贴纸。
```

还要求**把配色表里的 `描边 #4A3728` 整项删掉**。

**为什么废弃**：「只深一到两档」的明度差低于人眼在小尺寸下的分辨门槛，
等于要求模型画看不见的轮廓；删掉描边整项会让模型退回「几乎没有轮廓」。
用 `edge-strength.mjs` 量出竞品其实有清晰描边（明显轮廓占比 46.3% vs 我们 22.8%），
只是颜色是**中等深度的暖棕**而非黑色、粗细均匀而非包边。

</details>

**怎么量化验证**：`.build/scripts/seam-check.mjs` 打出每张图「最外圈两像素的
主色」。深棕（如 `70,44,29`、`116,96,77`）= 还有粗描边；
浅色（如 `235,201,162`）= 已经是同色系细线。这比肉眼看单张图可靠得多，
单看一张很难判断描边算不算「粗」。

该脚本还查两件事：四角 alpha（不透明 = 图是实心矩形、抠底失败）、
外圈不透明比例（>60% = 有烘进去的背景板）。

### ⚠️ 但「只深一到两档」会矫正过头 —— 小尺寸下轮廓等于没有

上一条纪律是为了消除贴纸感，**方向对、幅度错**。「只深一到两档」的明度差约
10~20，正好低于「肉眼在小尺寸下能分辨边界」的门槛。照它写出来的四张分区图
缩到 184px 之后，提示词里要的橡皮鸭 / 香皂 / 毛刷全部糊成几个像素点，
用户的反馈是「感觉没什么变化，图案还是没变」。

**别再靠肉眼判断，用 `edge-strength.mjs` 量。** 它算相邻像素明度落差
（Sobel 近似），实测洗浴间壁龛：

| | 竞品 | 我们（照「只深一两档」出的图） |
| --- | --- | --- |
| 明显轮廓占比（落差 >20） | **46.3%** | 22.8% |
| 强轮廓占比（落差 >50） | **26.5%** | 13.4% |
| 最深像素明度 | **91** | 59 |

**这三个数必须一起看才有意义。** 我们有比竞品**更深**的颜色（59 < 91），
却只有**一半**的轮廓 —— 说明深色全集中在一两块大面积暗部（木框暗部），
而竞品把对比度**均匀分配到每个小物件的边界**上。所以竞品元素更多却更清楚：
不是「元素少所以清楚」，是「每个元素都有足够边界对比，所以多也不乱」。

正确写法（描边**深三到四档**、用暖棕而非黑，并显式要求物件之间也要分开）：

```
描边要求（很重要）：每个物件都要有均匀的细描边，线宽一致、不要忽粗忽细，
也不要用黑色或深褐色把物体整个厚厚地包起来像贴纸。
描边统一用中等深度的暖棕色 #8B6A47，木质部分用更深一点的 #7A5A3C。
描边和它围住的填充色之间要有明显的明暗差别，让每个物件在缩小之后
仍然能一眼分辨出边界；不要用和填充色几乎一样深的颜色描边。
物件与物件相邻的地方也要有这样的描边把它们分开，
不要让两个物件的颜色直接糊在一起。
```

配色表里**要写回 `描边 #8B6A47`**（和上一条相反）——把描边整项删掉时，
模型会退回「几乎没有轮廓」。要的是换颜色，不是取消。
非木质部分给专属描边色（植物 `#5E8A55`、粉色 `#C4788A`），
全用一个棕色会让绿叶和粉布看起来脏。

**验收线**：`edge-strength.mjs` 的「明显轮廓占比 ≥ 25%」
（竞品整屏分区带 36.3%、单个壁龛 46.3%；本项目四张改后实测 22.5%~31.5%）。
确认改动是否真的上屏见 skill `asset-change-verification`。
`seam-check.mjs` 仍然要过（外圈主色仍须是浅色）——
两个脚本卡的是不同的东西：seam-check 防「整圈粗黑边框」，
edge-strength 防「内部物件之间没有边界」。**只过 seam-check 会得到一张
外圈干净、内部糊成一团的图。**

### 抠底必须用「局部容差」，因为模型会把背景烘成带渐变的奶油色

`cutout.mjs` 原来拿每个像素和**写死的白色**比。模型无视「纯白背景、不要渐变」
之后（实测花园 TL=`252,241,188` → BR=`206,176,139`，两端距离约 **93**），
症状是**一个像素都抠不掉**：打出 `816x816 -> 816x816`、退出码 0，
`seam-check` 报「四角 4/4 不透明 → 实心矩形」。

三种错误修法，都试过：

| 修法 | 结果 |
| --- | --- |
| 提高全局容差 | 阈值 80 时填充率掉到 90%、一个角被穿透 —— 开始啃画面 |
| 四角取中位数当键控色 | 渐变没有单一代表色，键出 `231,196,148` 而外圈是 `253,246,191` |
| 加重提示词「必须纯白 #FFFFFF」 | **连写两次都没用**，模型照样烘暖色底 |

正解是**局部容差**：泛洪时拿当前像素和「把它带进来的那个背景邻居」比，
而不是和一个全局颜色比。渐变逐像素变化很小，所以能一路蔓延过去，
而画面边界有描边挡着就停下。

**容差要往小调**，和直觉相反。实测育婴室：

| 局部容差 | 12 | 18 | 26 |
| --- | --- | --- | --- |
| 填充率 | **65%** | 13% | 4% |

容差大了会从描边的薄弱处**漏进画面内部**，把整只掏空。**12 是本项目的默认值。**

⚠️ 这条和描边纪律是**配套**的：局部容差能停在边界上，前提是物件有清晰描边。
**描边弱的图既读不清、也抠不干净** —— 两个问题同一个根因。

### 提示词里要写目标渲染尺寸

模型不知道图会被缩到多小。把「这张图会在手机上缩小到约 184 像素宽显示，
所以必须为小尺寸设计：每个物件都要有清晰可辨的独立轮廓，宁可物件画大一点、
也不要画很多细碎的小装饰」写进开头，比事后返工便宜。

尺寸从 `probe-artsize.mjs` 读运行时实际值，别猜 —— 图是 512 长边，
但框只有 152~202px，**等比缩放后永远被高度卡住**（见规则 `map-scroll-view`）。

### 「不够真实/不贴合」= 缺这三样，不是画风问题

第一版分区图和竞品参考摆在一起明显更假，逐条对下来差的不是笔触，是**内容**：

1. **内壁不换色 → 读不出「凹进去」**。内壁和墙同为米白时，壁龛成了「贴在墙上的
 白框」。要在提示词里**指定内壁用另一个色系**（本项目洗浴间内壁用浅蓝瓷砖
 `#C6E2F0` + 写明「能看到瓷砖接缝」），并要求「外框是一圈很厚的木框、
 有明显厚度」。
2. **没有落地物 → 悬浮感**。参考图每个功能角前面都垫着地垫/门垫/小地毯，
 而且**往外伸出来一点**。加一句「底部地面上铺着一块…、往外伸出来一点」
 就能解决，这是「站在地上」与「浮在墙上」的分界。
3. **内部细节太少**。「一个白盆 + 一个爪印」放大后空得明显。要**逐件点名**：
 浴缸写「四只小爪子形状的脚、一大团泡泡、几个飘着的圆泡泡、木柄刷子」。
 模型不会自己补，写几件给几件。

同理适用于代码绘制的底层：纯色墙读成「一块布」，加一层**极低对比**的爪印暗纹
（比条纹深一点即可）就变成「宠物主题的墙纸」；墙裙要有「踢脚板 + 一道更深的
上沿压条」，少了压条墙和地就像两块色纸拼在一起。

> 换账号后旧 `project_id` 会失效（报 `Project ... does not exist`），
> 用 `create-project` 建新的再 `project-add` / `project-switch`。
> `--download` 偶尔不落盘，用 `download --urls <图片URL>` 手动补下。

## 2. 抠底：边缘泛洪 + 局部容差

**全图色键会把小屋内部的白墙白窗一起抠成透明、留下窟窿。**
只清除「与画布外缘连通」的背景才对。

```bash
node scripts/cutout.mjs <输入png> <输出png> [容差=12]
```

**容差用 12。** 脚本已改为局部容差（不再和写死的白色比），
大容差会漏进画面内部把物件掏空 —— 完整原因见下面「抠底必须用局部容差」一节。

顺带自动裁到内容包围盒（+2px 边距），省掉手工裁图。

> 项目里另有 `pet-part-rig-prep/scripts/dewhite.ps1`，那是**全图色键 + 逐像素
> GetPixel**，适合小的分件图；处理 2048² 且内部有白色的整图请用本 skill 的 `cutout.mjs`。

## 3. 校验：叠两种底看

```bash
node scripts/check-alpha.mjs <目录> <输出png>
```

同时叠深绿底和奶油底。**残留白边** → 略微加大容差（上限 18）；
**主体被抠出洞** → **减小**容差（局部容差下漏洞来自容差过大，不是过小）。

改成局部容差后，「换背景色重新生成」基本不再需要 —— 实测连写两次
「背景必须纯白 #FFFFFF」模型都照样烘暖色渐变底，靠提示词解决这件事不可靠。

## 4. 缩放入包

```bash
node scripts/resize.mjs <输入png> <输出png> [长边=512]
```

面积平均降采样，**预乘后再平均**（否则透明像素的 RGB 会污染边缘）。

- 落位 `assets/resources/<模块>/<name>.png`，代码用 `resources.load('<模块>/<name>/spriteFrame', SpriteFrame)`。
- **首屏必需的图**要正方形且 2 的幂（iOS PVRTC，见 `docs/06-UI设计规范.md` §4.3）；
  地图这类走远程 Bundle 的不受此限，但仍要控体积。
- 新 PNG 需要**编辑器导入生成 `.meta`** 才能被加载，CLI 做不了。

## 5. 验收：读运行时真值

截图看不出交互对错。开无头浏览器连编辑器预览页，直接读引擎里的数：

```bash
node scripts/preview-probe.mjs            # 截图 + 控制台日志
node scripts/preview-probe.mjs --drag     # 拖动前后对比坐标
```

要点：只开**一个**预览页（WebGL 上下文有上限，见 `cocos-toolchain`）；
预览产物比源码旧就是编辑器还没编译，先比时间戳再查代码。

`node_modules` 的 —— 直接跑 `.cursor/skills/.../scripts/check-alpha.mjs` 会报

```powershell
Copy-Item .cursor\skills\game-art-from-ai\scripts\*.mjs .build\scripts\ -Force
cd .build; node scripts\check-alpha.mjs ..\assets\resources\map\props out.png
```

## 批量出图：提示词写进文件，别塞命令行

PowerShell 5.1 传含中文和引号的长提示词极易转义出错，报的错还指向被截断后的
乱码（见 `cocos-toolchain`）。可复用的做法：

- 一个元素一个 `.build/prompts/<name>.txt`
- 驱动脚本用 `[IO.File]::ReadAllText()` 读（认 BOM、按 UTF-8），
  **不要用 `Get-Content`**（按 ANSI 解码，中文会碎）
- 驱动脚本本身存成 **UTF-8 带 BOM**
- **提示词开头不能是 `*` 之类的特殊字符**。PowerShell 会把整个参数吃掉，
  报 `argument --prompt: expected one argument`。踩过一次：提示词以
  `**不要用深棕色描边` 开头，15 张图全部失败、10 秒内退出，
  而报错信息完全看不出是开头那两个星号的问题。
  对策两条都做：提示词里不写 markdown 强调符（模型不需要），
  驱动脚本再给 `$prompt` 加一个前导空格兜底。
- **批量任务要先单跑一张验证**。10 秒就"跑完"15 张 = 全部失败，
  跑完再看等于白等几分钟。

## 尺寸：按屏幕上的实际占位定，不要一律 512

道具在屏幕上最大不到 200 设计像素，长边 384 就够；512 是浪费。
`resize.mjs` 的长边参数按用途给：分区门面 512，环境道具 384。
